## 监控轮次设计（cron，interval@5m，Asia/Shanghai）
每轮（worker 任务正文）：
1. 用 browser.browse 打开 https://web.whatsapp.com/（default profile），等聊天列表加载（最多 45 秒）。
2. 若出现二维码页 → 报"WhatsApp 会话过期，需用户重新扫码"，本轮结束（不重复微信轰炸：掉线只报一次，记状态文件）。
3. 提取左侧聊天列表：聊天名、最后消息预览、时间戳、未读角标/数。只读，不点开、不发送。
4. 与 ~/hooks/state/whatsapp-chats.json（chat 名 -> {last_ts, last_preview}）比对：未读且最后消息非我方发出 → 新入站事件。
5. 有新入站 → 按"接手指令"处理；无 → 静默（记日志，不打扰用户）。

## 接手指令（新入站消息）
1. 点开该聊天，读最近 20 条，确认最新一条是客户发来、我方未回复；若用户本人正在手机上回复，不插话。
2. 按 ~/workspace/fb-ip/dm-playbook-combined.md + 公司 SOP 回复：客户用什么语言用什么语言；拆 2–4 条短消息（每条 1–2 短句）；先接话再答疑；价格零报价、不诊断、不承诺效果；目标=确认国家+带区号 WhatsApp（他已经在 WhatsApp 上，直接要国家即可）→ 交咨询团队。
3. 发送走浏览器。**审批卡**：若发送被审批卡拦住，不重试——按 2026-10-24 定规，立刻经 ~/workspace/wechat-bridge/.venv/bin/python send.py 发微信喊用户来点卡（中文说明），报告注明待点卡。
4. 合格客资（给出国家 / 明确咨询预约意向）→ 记 ~/workspace/fb-ip/leads.md，并在报告开头第一句写明，主 agent 立刻转报用户。
5. 每轮记 ~/workspace/fb-ip/dm-threads.md（WhatsApp 段）与当日 memory 日志。

## 风控与边界
- 只读自己账号的收件箱；不联系 FB 端未表达意向的陌生人（沿用 2026-10-23 风控口径）。
- 不做 WhatsApp 群发/广播；一次只处理已产生对话的客户。
- 监控本身只读；任何发送都经过审批卡（除非用户将来把该类设为始终允许，如 Messenger 那样）。
