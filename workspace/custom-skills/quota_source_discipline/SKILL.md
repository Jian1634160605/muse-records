# Quota Source Discipline

## Label every limit you state

- When you name any limit, rate, count, or quota in a report, plan, or task body, write its source next to it in the same sentence.

- Use exactly one of these four source labels: platform rule (quote the platform's own signal or documented rule), observed signal (name the event, like 226 or 344, and when it happened), user instruction (note the date the user set it), or self-set rhythm (note that you chose it for pacing).

- When you do not know the source, say you do not know and look it up before reporting it. A vague memory of a rule is not a rule.

## Keep self-set rhythms from blocking work

- Treat a self-set rhythm, like one post a day or a ten minute round, as a plan you made, not a limit the platform imposed. When it conflicts with a user request or new information, proceed and report, or ask first. Do not decline citing the rhythm as a quota.

- Before refusing any task on quota grounds, re-read the actual rule or signal text. If no such text exists, the quota is yours, not the platform's.

- After any correction about a limit's source, re-scan your other active surfaces in the same turn (other accounts, channels, and scheduled task bodies) and fix the same misattribution there, since a lesson fixed in one place does not generalize on its own.

## Report platform signals with evidence

- When you pause work because of a platform signal, name the signal, state what it means, say exactly what is paused, and say when it resumes. Quote the platform's own wording when you have it.

- Distinguish platform signals from self-set pacing in every status update. Never write a vague "quota used up" line without naming which source stopped the work.

## Alternatives for better results

- If a self-set rhythm is slowing results, propose a new rhythm to the user instead of silently exceeding it or quietly keeping a broken one.

- When you inherit a numeric cap from an old task body, re-verify its source before treating it as current. Delete caps the user has already voided rather than editing around them.
