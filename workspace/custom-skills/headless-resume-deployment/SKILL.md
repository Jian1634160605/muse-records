# 无窗口恢复运营 · 引导部署

只做一件事：把多账号 FB/IG 运营恢复起来，**全部动作一律无窗口后台跑**。这个 skill 只讲引导和部署：agent 怎么装、怎么升版、怎么验证无窗口、恢复跑的节奏和执行步骤。

**这个 skill 不含的内容**：私信话术、评论话术（另见话术文件）；账号分组、具体哪个号分到哪一组（另见账号矩阵文件）；剪辑（Concat 单独沟通，不在本方案内）。

## 什么时候用这个 skill

- 在一台装好 ixBrowser 的 Windows 电脑上部署或升级 agent 时用。
- 验证无窗口是否真的生效时用。
- 恢复多账号猎手加私信运营时用。
- agent 变慢、超时、弹窗时排查用。

## 目标

全部账号、全部动作一律无窗口后台跑，恢复多账号的猎手加私信运营，拿到合格客资（带国家区号 WhatsApp 加国家）。

## 无窗口硬规则（长期，不可违反）

- 所有账号、所有动作一律无窗口后台跑，任何时候不许在用户电脑上弹浏览器窗口。
- “收集数据”“恢复运营”等授权不等于授权弹窗；授权做一件事不等于授权弹窗。
- **操作前先问**：每次操作账号之前，先问用户一句，确认是后台跑、不弹窗，用户点了头再动手。
- 如果某次操作有弹窗风险，必须**提前**告诉用户、等他定，不能先干了再说。
- 无窗口没验证通过前，不得批量操作账号。验证方法：先拿一个号单独测通（打开、读 feed、关掉，全程不弹窗），确认后再往下做。

## 架构

- 在装 ixBrowser 的电脑上跑一个常驻小程序（ixBrowser agent），Muse 从外面发指令，小程序在本机操作浏览器。
- ixBrowser 的 Local API 只听本机 127.0.0.1:53200，浏览器调试端口也只听本机，Muse 从外面够不着，所以小程序必须贴着浏览器跑。
- Muse 和电脑之间走 Tailscale 内网，agent 监听 0.0.0.0:8765。
- 视频发布不走浏览器，FB 走 facebook-cli，IG 走 instagram-cli。
- 定时任务跑在 Muse 的调度器里，不在电脑上。

## agent 版本与并发修复

### v8 的瓶颈（已确认）

v8 里有一把全局锁，所有浏览器操作（open、close、check、tabs、goto、eval、click、type、shot、attach）全部串行，一次只做一件事。多个号并发时所有请求堵在这把锁后面，慢操作一卡就全超时。用户电脑硬件不是瓶颈（i5-12400F、32GB 内存、RTX 3060 Ti、固态）。

### v9 的改法

把全局锁换成“每个号一把锁”加“每个线程一个 driver 实例”。不同号并行跑，同一个号仍串行（防抢标签页）。本地验证：3 个不同号并行 0.50 秒（v8 串行要 1.50 秒），同一个号 3 次操作仍串行 1.50 秒。

### v9 文件

- 源码目录：`~/workspace/ixbrowser-driver/agent-v9-perprofile-lock/`（agent 主程序 VERSION=9，driver 不变）。
- 打包 zip：`~/workspace/ixbrowser-driver/ixbrowser-agent-v9-perprofile-lock.zip`（7 个文件：主程序、driver、requirements.txt、README、start.bat、install.bat、stop.bat）。
- 转换脚本：`~/workspace/ixbrowser-driver/transform_v8_to_v9.py`（从 v8 生成 v9）。

## 部署 v9（走 agent 自带更新接口）

1. 先把 v9 zip 上传拿到直链（链接会过期，部署前现传现用）。
2. 调 agent 的更新接口，传 zip 直链和版本号 9。接口会先校验 zip，校验通过才替换文件并重启；校验失败或重启失败自动回滚到旧版。
3. 等 30 秒左右，调 `/health` 核对版本号，返回 version 为 9 才算部署成功。
4. 部署成功后不要直接恢复跑，先做单号无窗口测试（见下节）。

部署前先确认 agent 在线（`/health` 返回 ok）。部署会重启 agent，重启期间不要发其他操作。

## 验证无窗口（单号测试，必须先做）

部署后、恢复跑之前，必须先拿一个号单独测通。步骤：

1. 先问用户一句，确认现在可以测、后台跑、不弹窗，用户点头再动手。
2. 查当前已开列表，应为空（没有号开着）。
3. 打开测试号，传无窗口参数（见下文“无窗口参数现状”）。
4. 跳到 facebook.com，读页面，确认登录态正常、feed 能读到。
5. 关掉测试号。
6. 再查已开列表，应为空，确认号已关、没有残留窗口。

**判定标准**：全程用户电脑上不出现浏览器窗口。只要弹了一次窗口，就算没通过，停下来排查，不许继续往下做、不许批量开号。

### 无窗口参数现状（2026-11-18 实测，未通过）

- 尝试过的办法：打开 profile 时传启动参数 `--headless=new`。
- 实测结果：2026-11-18 18:52 单号测试，参数传过去了，号能打开、feed 能读、也能关掉，但**用户电脑上还是弹出了一个可见的 Facebook 窗口**。也就是说这个办法没有生效。
- 结论：`--headless=new` 这条路目前未经证实有效，不能当作已解决。在找到真正有效的无窗口办法并实测通过之前，不得批量操作账号。
- 下一步排查方向：确认 ixBrowser 的 Local API 是否支持无窗口启动、参数名和传法是否正确、是否需要改 profile 自身的设置而不是启动参数。

## 恢复跑的节奏

- 60 分钟一轮，各号错开跑；同号的猎手与私信错开 30 分钟。
- 并发上限：任何时候同时开着的 profile 不超过 3 个（起测可从 2 个开始，稳住再往上加）。如果 agent 变慢，优先拉长间隔、不硬撑。
- 恢复前先复核待发的已过审评论草稿：目标帖还在不在、评论还合不合适，不合适的打回重写，不硬发。
- 恢复跑只跑用户自己的默认分组号，组员账号等她们装机上线、有数据了再分阶段接进来。

## 每天的数据报告

- 每天出一份按号分的数据：每个号发了几条、播放点赞评论多少、私信在聊几条、出了几个客资。
- 报告发 FB 运营报告旁聊，主聊只报客资和致命问题。
- 用户看了数据再定内容方向，Muse 按方向做内容、给内容指导建议。
- 报告要写清后续如何改进、怎么推进、时间节点。
- 默认分组账号会增减（用户把账号分配给组员是正常现象），以当时实际为准。

## 发视频（只走后台）

- 一个视频等于 FB 加 IG 两个平台才算发完，同一账号不发重复视频。
- 所有发布一律走后台，绝不走浏览器发帖框。
- FB Reel 只发单个视频文件（facebook-cli），不带封面图；IG Reel 才带封面（instagram-cli）。
- 发布时间：下午 4 点开始发，每个视频间隔 2 小时，同一轮次所有账号都发，但每账号之间错开几分钟，不要同一秒齐发。
- 视频文案由 Muse 自己写，对外英文，钩子加具体设计点加互动问题，AI 视频注明 AI-generated video for illustration。
- 发完立即做自评引流评论（引导点主页 WhatsApp，不贴链接、不贴电话），再让发了视频的账号互相看其他账号发的视频，把完播率拉起来。

## 硬规则（执行时对照）

- 发布一律走后台，绝不走浏览器发帖框。
- 一个视频等于 FB 加 IG 两个平台才算发完，同一账号不发重复视频。
- 视频 16 点起发，每条间隔 2 小时，同一轮次各账号错开几分钟。
- 送达必须经 Messenger CLI 查到线程存在且 snippet 为我方消息，才可汇报已发；只看浏览器气泡等于未核验，不得汇报送达。
- 内容先经 E07 90 分以上加总管确认，长内容发布还需老板点头，红线一票否决。
- 视频先审后排，老板发来的成品视为已批准。
- 429 只是瞬时限流，短暂退避后重试，不停查、不等明天、不自己设限；226 或 344 即停该号，核实后不盲重试。
- 对外文案一律英文，视频文字中英双译，跟老板沟通用中文。
- 汇报只说重点和结果，不讲过程；只报问题，没问题不报。
- 总管只派活不亲自干活（facebook-cli 发布与核验除外），派活以总管 Muse 身份发，不借老板名义。
- 浏览器操作默认后台跑，不打开给人看，只有老板说要看时才打开。
- 令牌一机一个，绝不共用；登录态现登，不拷文件。
- 浏览器活由主 agent 直接派发，不派普通子代理（子代理没有实时浏览器控制权限）。
- 凭据卫生：密码、cookie、2FA、代理值、令牌不写记忆，不在聊天复述；查环境状态只取 name 加 is_running，不打印接口原文。

## 常见问题

- profile 显示已开但本机找不到调试地址时，先 close 再 open 即可恢复。
- TargetClosedError 多为页面已关，重开重试可过。
- code 2012 是窗口云备份中，稍后再试。
- 每次重新登录都会产生新的 2FA 验证请求，须点最新那条。
- IG 每日限额提示时会话本身有效，不用重登，等次日。
- 浏览器崩溃丢登录态时先停浏览器，把 cookies.sqlite.bak 拷回 cookies.sqlite 并删掉 wal 和 shm，再拉起即恢复；操作前先把当前 cookies.sqlite 备份到一边，勿在浏览器运行时拷。
- agent 同时开 7 个 profile 会拖死（v8 实测），v9 改锁后上限待重新验证，起步按同时不超过 3 个来。
- `check()` 会把已关的 profile 重新拉起；确认 profile 是否已关只用已开列表核对，勿对已关的号调 check。
