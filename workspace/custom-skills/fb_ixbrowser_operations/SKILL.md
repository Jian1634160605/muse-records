# Facebook 指纹浏览器多账号运营

用 ixBrowser 指纹浏览器加常驻小程序加后台发布加 Concat 剪辑，在多台电脑上跑多账号 FB 和 IG 获客。先读 references/full-manual.md 再动手，话术全文在 references 里，程序在 scripts 里。

## 什么时候用这个 skill

- 在一台新 Windows 电脑上搭起整套 FB 运营时用这个 skill。
- 操作已搭好的多账号矩阵时用这个 skill。
- 发视频、跑猎手、盯私信、剪辑、核验账号时用这个 skill。
- 不要用这个 skill 做 X 运营，不要用它发浏览器发帖框。

## 架构

- 在装 ixBrowser 的电脑上跑一个常驻小程序，Muse 从外面发指令，小程序在本机操作浏览器。
- ixBrowser 的 Local API 只听本机 127.0.0.1:53200，浏览器调试端口也只听本机，Muse 从外面够不着，所以小程序必须贴着浏览器跑。
- Muse 和新电脑之间走 Tailscale 内网，小程序监听 0.0.0.0:8765，Concat 桥监听 0.0.0.0:8766。
- 视频发布不走浏览器，FB 走 facebook-cli，IG 走 instagram-cli。
- 定时任务跑在 Muse 的调度器里，不在电脑上，见 references/cron-inventory.md。

## 在新电脑上装机

- 装 Windows 10 或 11，装 Python 3.12 以上并勾上 Add to PATH。
- 装 ixBrowser 客户端，在设置里打开 Local API 开关。
- 装 Tailscale，进同一个 tailnet。
- 装 Concat v0.2.11 到 D:\Concat\concat.exe。
- 把 scripts/agent-v6 解压到固定文件夹，比如 D:\ixbrowser-agent，以后别挪地方。
- 复制 scripts/agent-v6/config.example.json 为 config.json，把里面的占位符换成一个新生成的随机长字符串，每台电脑一个独立令牌，绝不复用旧电脑的令牌。
- 双击 install.bat，建桌面快捷方式，加开机自启，立即后台启动。
- 打开 http://<新电脑 Tailscale IP>:8765/health 验活，应返回 ok 且 version 为 6。
- 把 scripts/concat/concat_bridge.py 拷到 D:\ixbrowser-agent\concat_bridge.py，把 concat_bridge_startup.bat 放进 Startup 文件夹，双击一次立即启动。
- 打开 http://<新电脑 Tailscale IP>:8766/health 验活，应返回 ok 且 mcp_running 为 True。
- 把新电脑的 Tailscale IP 和新令牌告诉 Muse 登记，登记后才能像操作原机一样操作这台电脑。
- 在新电脑的 ixBrowser 里新建 profile，每号一个，在自己的 profile 里登录一次 Facebook 或 Instagram，真人验证要号主在自己手机上点批准。
- 打标签，tag 为 fb 的是 Facebook，tag 为 ins 的是 Instagram，放进默认分组。
- 登录态核验用 scripts/driver/flows/check_default11.py 的思路逐个 open 再 check 再 goto 对应网址，fb 去 facebook.com，ins 去 instagram.com，截图看登录名对不对，feed 正常不正常。
- 核验全程后台跑，不在桌面打开给人看，查完就关，不留窗口。

## 账号矩阵

- 按 10 个算，Victoria 是主号，不计在这 10 个里。
- 默认分组的号是老板本人的账号，其他分组是组员各自的账号，不动，不核验，不写进矩阵。
- 完整矩阵见 references/account-matrix.md，方向分配见 references/full-manual.md。
- 新并进来的号方向未定时，等老板定，建议 FB 按 3 个鼻子加 3 个面提分。

## 猎手

- 每 10 分钟一轮，全天滚动，每轮最多 3 条新评论，不设全天条数上限，量只受平台限制。
- 先读 references/competitor-watchlist.md 拿监控名单，看最近 2 到 3 天高播放帖子的评论区，找问价、问预约、问哪里做、要联系方式、问维持多久、问恢复期、说想做的人。
- 再扫求推荐和求助帖，重点看公开群组，每轮扫 1 个群的最新帖，群里发现的合格意向先记收集表再触达。
- 每轮重读已评论帖的回复楼层，包括他人评论下面的回复楼层，楼主回复了我方评论当天就接话。
- 达到私信门槛就转私信流程，门槛是问价、要联系方式、明确想做。
- 评论写 2 到 4 句，先一句勾住他的话，再留一个让他想回的问题，不列长清单，不讲课。
- 每条评论必须带楼主原帖独有的一个细节，比如年龄、部位、国家、面诊阶段、最担心的点、已提到的医生或诊所。
- 钩子轮换用恢复时间线、避坑点、面诊必问清单、过程案例，结尾问题改二选一。
- 发评论前除筛楼主外还要扫热门评论者，带推广嫌疑特征的标注为邻近推广嫌疑，绝不回复，不 @，不接话。
- 顶楼评论要点名楼主或复述楼主原问题。
- 评论区不提来找我做，不留 WhatsApp、链接、电话，不贬低同行。
- 去重台账发之前重读，发完一条立即记一条，不攒到轮次结束，台账里出现过的父评论、帖子、人一律跳过。
- 短评论先经 E07 短内容卡打分 90 分以上加总管确认才能发，长内容发布还需老板点头。
- 遇 429 短暂退避后重试，429 只是瞬时限流，不是每日额度，不停查，不等明天，不自己设限。
- 猎手主路线是浏览器，不走 CLI 评论读取，不走任何代理，旧静态 IP 方案已删。

## 私信盯守

- 完整话术在 references/dm-playbook-combined.md，来源 A 是公司 SOP，来源 B 是话术库，细节以原文为准。
- 唯一 KPI 是合格客资，带国家区号 WhatsApp 加国家。
- 准用户是海外加真实手术意向加需求对公司品相加真人个人号，同行、机构号、已术后求助、纯赞美吃瓜、明确拒绝出国、广告号完全不联系。
- 私信一次只发一条，等对方回话再发下一条。
- 首条禁直接索号，只接住他原帖的具体问题给一句实在回答，加问一个跟他本人有关的问题，每人说法不同。
- 漏斗是第 1 到 2 条接问题加问本人问题，不提号、WhatsApp、咨询团队，第 3 条给面诊钩子，第 4 条起给干货再推留号。
- 面诊钩子是秦浩医生线上远程视频面诊，每周 2 个免费名额，先到先得，具体时间加名额加下一步，不直接要号。
- 已发 3 条以上未给钩子的线程下一条即补钩子。
- 客户主动问价、问地点、问怎么约是推进信号，只答离成交最近的一个问题，直接要带区号 WhatsApp，不给先发链接这类拖延选项。
- 给号后 45 秒内回咨询顾问很快联系你，区号核对写进移交备注。
- 价格零报价零区间，问价一律按公司 SOP 回应费用看个人情况，需面诊确定，咨询团队会联系。
- 地点只在他问远不远、在哪做时再说，只说相关的，集团只说重庆、上海、台湾，未核实城市只说可以安排对接，具体由咨询团队确认，巴黎没有服务点，绝不虚构地址。
- 不愿留号给咨询链接，私信可发，评论区不贴。
- 跟进节奏是 B-18 在 24 到 48 小时，B-19 在 3 到 7 天，之后每隔 2 到 3 天可再补一条真人式再询问，最多再补 2 条，明确拒绝或拉黑立即停。
- 表情看状态宁少勿多，正面或轻松时可点赞或爱心，担忧、纠结、问正事时不点，医疗场景不用大笑或生气表情。
- 送达必须经 Messenger CLI 查到线程存在且 snippet 为我方消息，才可汇报已发，只看浏览器气泡等于未核验，不得汇报送达。
- 私信盯守 5 分钟一轮，客户雷达 1 小时一扫，猎手 10 分钟一轮，新私信 30 秒实时哨兵。
- 新好友出现要立即筛查并联系，只联系收集表里的人和评论过的意向客户中的真人个人号。
- 待处理好友请求每轮经浏览器核查，疑似真实意向客户先通过再立即私信，身份拿不准先报老板再定。

## 发布视频

- 一个视频等于 FB 加 IG 两个平台才算发完，同一账号不发重复视频。
- 所有发布一律走后台，绝不走浏览器发帖框。
- FB Reel 只发单个视频文件，用 facebook-cli post create 加 message 和 file，不带封面图。
- IG Reel 才带封面，用 instagram-cli post-feed 加 account-id、file、cover、caption。
- 视频文件夹在桌面秦浩视频的未发视频里，每个视频一个文件夹，里面带封面，发完移到已发视频，并在该视频文件夹里写发布结果.txt。
- 需要视频数等于 max(FB 账号数，IG 账号数) 乘每账号发几条。
- 统一从下午 4 点开始发，每个视频间隔 2 小时，同一轮次所有账号都发，但每账号之间错开几分钟，不要同一秒齐发。
- 视频文案由 Muse 自己写，对外英文，钩子加具体设计点加互动问题，AI 视频注明 AI-generated video for illustration。
- 发完立即做两件事，先在本号评论区留一句自评引流评论，引导点主页 WhatsApp 联系链接，评论本身不贴链接，不贴电话，再让发了视频的账号互相看其他账号发的视频，把完播率拉起来。
- IG 后台须先连账号，没连上之前 IG Reel 一直待发，不走浏览器顶。
- AI 视频过 E07 90 分可直接发，事后报链接，真实患者视频仍先审后排。
- 内容先经 E07 90 分以上加总管确认，长内容发布还需老板点头，红线一票否决。
- 选片要过程型，不要单人大脸成果特写，淡半透明签名可接受，大水印和中央水印弃用，疑似假对比禁用。
- 非本案患者不露脸，只取切口、器械、手部近景，本案患者可露脸。
- 视频先审后排，所有确定好的视频必须先发老板看，确认后才能排期发布，老板发来的成品视为已批准，直接发不再另等过目。
- 发视频必剥原音轨只留我方一条，ffprobe 核等于 1，选曲对标源爆款氛围和 BPM，现代轻快。
- 每天发布前先看前一天数据再定当天内容，读不到注明未读到，不编数据。
- AI 面诊视频标准见 references/ai-video-routine.md。

## 剪辑

- 剪辑一律走 Concat 经桥，不再手拼 ffmpeg。
- 桥在新电脑上跑，端口 8766，令牌与 agent 共用 config.json 里的那一个。
- Muse 侧用 scripts/concat/concat_client.py 里的 ConcatBridge 类调桥。
- 流程是建项目，导视频，上时间线，加标题，导出，成品 1080 乘 1920，h264，30fps。
- 成片仍过 E07 90 分门。
- 剪映没有公开的命令行剪辑接口，草稿 JSON 是未公开格式，改起来脆弱，需要剪映特有效果时再走剪映草稿路线。
- 用户电脑上还有 ffmpeg 9.0.2，自动化剪辑走 ffmpeg 更稳，但今后一律走 Concat 经桥。

## 硬规则

- 发布一律走后台，绝不走浏览器发帖框。
- 一个视频等于 FB 加 IG 两个平台才算发完，同一账号不发重复视频。
- 视频 16 点起发，每条间隔 2 小时，同一轮次各账号错开几分钟。
- 私信一次只发一条，等回再聊，首条禁直接索号，零报价。
- 送达必须 Messenger CLI 查到线程且 snippet 为我方消息才算已发。
- 内容先经 E07 90 分以上加总管确认，长内容发布还需老板点头，红线一票否决。
- 视频先审后排，老板发来的成品视为已批准。
- 429 退避重试，226 或 344 即停该号，核实后不盲重试。
- 对外文案一律英文，视频文字中英双译，跟老板沟通用中文。
- 汇报只说重点和结果，不讲过程，只报问题，没问题不报。
- 总管只派活不亲自干活，facebook-cli 发布与核验除外，派活以总管 Muse 身份发，不借老板名义。
- 浏览器操作默认后台跑，不打开给人看，只有老板说要看时才打开。
- 令牌一机一个，绝不共用，登录态现登，不拷文件。
- Bertie 已退役，任何 Bertie 的发布或派活一律拦下，Bertie 绝不走 browser.browse。

## 常见问题

- profile 显示已开但本机找不到调试地址时，先 close 再 open 即可恢复。
- TargetClosedError 多为页面已关，重开重试可过。
- code 2012 是窗口云备份中，稍后再试。
- 每次重新登录都会产生新的 2FA 验证请求，须点最新那条。
- IG 每日限额提示时会话本身有效，不用重登，等次日。
- 浏览器活由主 agent 直接派发，不派普通子代理，子代理没有实时浏览器控制权限。
- 凭据卫生是密码、cookie、2FA、代理值、令牌不写记忆，不在聊天复述，查环境状态只取 name 加 is_running，不打印接口原文。
- 浏览器崩溃丢登录态时先停浏览器，把 cookies.sqlite.bak 拷回 cookies.sqlite 并删掉 wal 和 shm，再拉起即恢复，操作前先把当前 cookies.sqlite 备份到一边，勿在浏览器运行时拷。
